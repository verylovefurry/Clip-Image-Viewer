# CSP 독립 레이어 렌더링 분석

## 결론

CSP를 실행하거나 PSD로 변환하지 않고 CLIP 내부의 저장 픽셀과 개체 정보를 읽어
레이어 ON/OFF를 구현할 수 있다. **현재 구현이 모든 문서와 모든 가시성 조합에서
CSP와 완전히 동일하다는 뜻은 아니다.** 특히 브러시, 톤, 효과와 축소 합성은 추가 검증이 필요하다.

## 새 경로

1. `LayerRenderMipmap`의 연결을 따라 실제 외부 청크가 존재하는 레이어 래스터를 읽는다.
2. 텍스트는 `TextLayerAttributes`의 태그 50으로 개체별 `Offscreen.MainId`를 찾는다.
   `Offscreen.LayerId`가 해당 레이어와 일치하는지 확인하고 태그 42의 좌표에 배치한다.
   글꼴, 글자 배치와 개체 변형을 다시 적용하지 않는다. 태그 72의 보조 오프셋도 중복 가산하지 않는다.
3. 텍스트 캐시가 완비되지 않은 경우에만 기존 글꼴 기반 재구성을 사용한다.
   저장 캐시가 있다고 해서 별도의 레이어 테두리나 톤까지 모두 적용된 것으로 간주하지 않는다.
4. 벡터는 헤더의 실제 반지름 위치, 브러시 ID, 필압 곡선, 속도 곡선과 고정 크기 플래그를 읽는다.
   필압·속도·평활화·기울기를 다른 필드로 혼동하지 않는다. 선 색상과 불투명도는 선별로 적용한다.
5. 별도의 RGBA 합성기가 CLIP 합성 모드, 원본 0~256 불투명도, 알파, 클리핑을 처리한다.
   알 수 없는 혼합 모드를 임의로 표준 모드로 바꾸지 않는다.
6. 저장 마스크의 1비트와 8비트 형식을 구분한다. 전부 검은 마스크는 레이어를 숨긴다.
   흰 알파 영역을 확장한 테두리는 글자/선 아래에 놓아 원래 잉크를 덮지 않는다.
7. 레이어 이미지와 하위 트리 합성을 캐시한다. 폴더 ON/OFF 때 개체 파싱이나 글꼴 렌더링을 반복하지 않는다.

이 경로는 JS, sql.js와 Sharp만 사용한다. CSP 실행 파일, CSP DLL, 외부 변환 프로그램을
필요로 하지 않으며 CLIP 원본을 수정하지 않는다.

## 확인한 범위

- 로컬 만화 샘플 14개: 레이어의 말단 항목 482개, 텍스트 레이어 73개, 텍스트 개체 415개.
- 텍스트 개체 415개 모두 소유 레이어가 일치하는 저장 Offscreen 데이터를 찾고 디코딩했다.
- 테스트에서 글꼴 이름·크기·쓰기 방향을 바꿔도 캐시 경로의 결과 PNG는 동일했다.
  이는 캐시 사용을 입증하지만 전체 문서가 CSP와 픽셀 단위로 일치함을 입증하지는 않는다.
- 원본 수정 방지, 다른 레이어 캐시 차용 방지, 1비트 검은 마스크, 테두리의 잉크 보존을
  합성 CLIP 회귀 테스트로 검사한다.
- 공개 `animeops/clip-tools`의 `test000.clip` 기본 래스터 문서는 독립 재합성 결과가
  파일 안의 CSP CanvasPreview와 픽셀 단위로 일치했다. 함께 제공된 별도 PNG와의 비교는 일치하지 않았다.
- 실제 앱의 page0006 테스트에서 캐시 준비 이후 래스터 ON/OFF는 10~43ms,
  폴더 ON/OFF는 8~25ms였다. 최초 래스터 요청은 약 2.65초였고, 이후 폴더 첫 요청은 약 147ms였다.
  측정값은 해당 PC·문서에 한정되며 모든 문서의 성능 보장은 아니다.

## 남아 있는 차이

전체 독립 재합성을 저장된 CSP 미리보기와 비교하면 14개 만화 샘플은 모두 픽셀 단위로
일치하지 않는다. 현재 채널 RMSE는 약 37~72, 2 이상 차이 나는 픽셀은 약 23~66%다.
일치하는 기본 래스터 문서나 개체 캐시 검사만으로 완전 동등성을 선언해서는 안 된다.

- CSP 톤의 점 무늬, 위상, 밀도와 네이티브 해상도에서의 효과 적용 순서가 아직 근사다.
- 벡터는 필압 등 저장 속성을 적용하지만 CSP의 곡선 보간, 브러시 끝 모양·텍스처,
  산포·흐름 및 모든 난수 규칙을 완전히 구현한 것은 아니다.
- 테두리의 원형 커널, 소수 두께와 원래 해상도에서의 처리 결과는 더 정교한 구현이 필요하다.
- 텍스트 캐시가 없거나 3D/전용 효과에 필요한 독립 데이터가 없는 문서는 추가 경로가 필요하다.
- 현재 기본 화면은 CSP 저장 미리보기를 보여 주며, 레이어 조작 때 변경 영역만 독립 합성
  결과로 교체하는 보존 경로도 유지한다. 이는 완전한 CSP 렌더러를 대체하지 않는다.

완전한 독립 렌더러를 목표로 하려면 네이티브 해상도의 타일 합성, 정확한 브러시 엔진,
톤·효과 엔진을 구현하고 각 레이어/폴더의 숨김·표시 상태에 대한 CSP 기준 이미지를
대조해야 한다. 저장 상태의 전체 미리보기 하나만 맞추는 검증으로는 부족하다.

## 재현

```bash
npm test
npm run test:samples
npm run test:layers
node scripts/analyze-clip-rendering.js
```

마지막 명령은 로컬 샘플을 사용해 `preserveOriginal: false` 독립 합성과 CSP CanvasPreview를
비교하고 작업 폴더 바깥의 `outputs/clip-renderer-research`에 PNG와 JSON 보고서를 생성한다.
개인 CLIP 파일과 출력 이미지는 소스 저장소나 배포물에 포함하지 않는다.
